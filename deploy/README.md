# Розгортання Budsmet

Застосунок зберігає всі кошториси, історію цін і довідник в одному файлі SQLite.
Тому головна вимога до майданчика — **постійний диск**: без нього база
стиратиметься при кожному перезапуску. Саме на цьому відпадає більшість
безкоштовних тарифів.

## Куди можна поставити безкоштовно

| Майданчик | Постійний диск | Картка | Коли обирати |
|---|---|---|---|
| [**Oracle Cloud Always Free**](oracle/README.md) | так, 47 ГБ+ | для верифікації | 2 CPU / 12 ГБ — найпотужніша безкоштовна машина, якщо вдасться зареєструватись |
| [**Google Cloud Always Free**](gcp/README.md) | так, 30 ГБ | для верифікації | якщо Oracle відмовив: 1 ГБ пам'яті, лише регіони США |
| [**Свій комп'ютер + Cloudflare Tunnel**](tunnel/README.md) | так | не потрібна | без реєстрацій і картки; працює, поки увімкнений комп'ютер |
| Render, Koyeb, Fly.io, Hugging Face | **ні** | — | не підходять: база не переживе перезапуску |

Про безкоштовні тарифи PaaS варто знати окремо: у Render постійний диск лише
платний, у Koyeb безкоштовна машина **не може підключити** том (ті «2 ГБ SSD» —
тимчасові й зникають при перезапуску), у Fly.io безкоштовного тарифу більше
немає, а Docker-простори Hugging Face тепер вимагають платного акаунта.

## Публікація змін — покроково

Нижче — що робити, коли в репозиторії з'явилась нова версія, а на машині
працює стара.

### Крок 1. Підключитись до машини

У Cloud Shell (кнопка **`>_`** у консолі Google Cloud) або в себе в терміналі:

```bash
gcloud compute ssh budsmet --zone=us-central1-a
```

Запрошення має змінитись на щось на кшталт `ubuntu@budsmet:~$`.

### Крок 2. Перевірити, чи ввімкнене автооновлення

```bash
systemctl status budsmet-autoupdate.timer
```

- Бачите **`Active: active (waiting)`** → автооновлення працює, переходьте
  до кроку 4: нова версія приїде сама протягом 10 хвилин.
- Бачите **`Unit ... could not be found`** або `inactive` → переходьте до кроку 3.

Вийти з перегляду — клавіша `q`.

### Крок 3. Оновити вручну (і ввімкнути автооновлення на майбутнє)

```bash
curl -fsSL -o /tmp/budsmet-setup.sh \
  https://raw.githubusercontent.com/KAZUM0RA/Budsmet/claude/web-app-cost-estimates-l1x9ef/deploy/vm/setup.sh
sudo bash /tmp/budsmet-setup.sh --login ВАШ_ЛОГІН --domain ВАШ.ДОМЕН
```

Підставте свій логін і домен. Пароль без `--password` не змінюється.

Беремо інсталятор окремим файлом, а не запускаємо той, що лежить на машині:
скрипт оновлює той самий каталог, у якому лежить сам, і без цього git підмінив
би його просто під час виконання.

Наприкінці має з'явитись таблиця з рядками:

```
  Стан служби   працює
  Автооновлення увімкнено, перевірка кожні 10min
```

Якщо в рядку «Стан служби» щось інше — дивіться крок 6.

### Крок 4. Дочекатись і перевірити, що версія оновилась

```bash
git -C /opt/budsmet/app log -1 --format='%h %s'
```

Ви побачите останній коміт, який стоїть на машині. Порівняйте його з
[останнім комітом у гілці](https://github.com/KAZUM0RA/Budsmet/commits/claude/web-app-cost-estimates-l1x9ef)
— мають збігатись.

Якщо чекаєте на автооновлення і хочете не чекати:

```bash
sudo systemctl start budsmet-autoupdate
```

### Крок 5. Відкрити застосунок

Зайдіть на свою адресу у браузері й **оновіть сторінку з очищенням кешу** —
`Ctrl+F5` (у Windows) або `Cmd+Shift+R` (у macOS). Без цього браузер може
показувати стару версію інтерфейсу.

### Крок 6. Якщо щось не так

```bash
sudo journalctl -u budsmet -n 40 --no-pager            # чому не працює застосунок
sudo journalctl -u budsmet-autoupdate -n 40 --no-pager # що робило автооновлення
```

Невдале оновлення не лишає застосунок лежачим: якщо нова версія не піднялась,
код автоматично повертається на попередню, і в журналі буде рядок
`✓ Відкат виконано`. У такому разі надішліть цей журнал розробнику.

## Автоматичне оновлення

Після кроку 3 машина сама перевіряє репозиторій кожні 10 хвилин і встановлює
нову версію, щойно вона з'являється.

```bash
systemctl status budsmet-autoupdate.timer     # чи увімкнено і коли наступна перевірка
journalctl -u budsmet-autoupdate -n 50        # що робилось під час останніх перевірок
```

Змінити частоту або вимкнути:

```bash
sudo /opt/budsmet/app/deploy/vm/setup.sh --update-every 30min --login ВАШ_ЛОГІН
sudo /opt/budsmet/app/deploy/vm/setup.sh --no-auto-update --login ВАШ_ЛОГІН
```

**Захист від невдалого оновлення.** Після встановлення нової версії застосунок
перевіряється на працездатність. Якщо він не піднявся — код повертається на
попередню версію, залежності перевстановлюються, служба запускається знову.
Непрацездатна версія запам'ятовується і повторно не встановлюється, доки в
гілці не з'явиться новий коміт. База даних під час усього цього не змінюється.

> Увага: усе, що потрапляє у гілку, автоматично опиняється на сервері.
> Якщо це небажано — вимкніть автооновлення і оновлюйтесь вручну.

## Оновлення вручну на вже налаштованій машині

Коли автооновлення вже ввімкнене, а треба негайно:

```bash
sudo /opt/budsmet/app/deploy/vm/update.sh
```

## Що всередині

- [`vm/`](vm) — скрипти для будь-якої машини з Ubuntu 22.04/24.04:
  - `setup.sh` — повне встановлення: залежності, служба автозапуску, nginx зі
    входом за паролем, HTTPS від Let's Encrypt, шрифти для кирилиці в PDF,
    відкриття портів, щоденна резервна копія;
  - `update.sh` — оновлення до останньої версії (з копією бази перед тим);
  - `backup.sh` — резервна копія без зупинки застосунку;
  - `restore.sh` — відновлення з копії;
  - `autoupdate.sh` + `budsmet-autoupdate.{service,timer}` — регулярна перевірка
    репозиторію і встановлення нових версій;
  - `budsmet.service`, `nginx-budsmet.conf` — шаблони конфігів.
- [`oracle/`](oracle/README.md), [`gcp/`](gcp/README.md) — покрокові інструкції
  для конкретної хмари (кроки в консолі відрізняються, скрипти однакові).
  Для Google Cloud є ще `gcp/create-vm.sh` — створює машину правильної
  безкоштовної конфігурації однією командою з Cloud Shell.
- [`tunnel/`](tunnel/README.md) — доступ через інтернет без сервера взагалі.

## Найкоротший шлях

На свіжій машині з Ubuntu, коли вона вже створена і порти 80/443 відкриті:

```bash
sudo apt-get update && sudo apt-get install -y git && \
sudo git clone --depth 1 --branch claude/web-app-cost-estimates-l1x9ef \
  https://github.com/KAZUM0RA/Budsmet.git /opt/budsmet/app && \
sudo /opt/budsmet/app/deploy/vm/setup.sh --domain ваш.домен --login ваш_логін
```

Скрипт наприкінці покаже адресу, логін і пароль. Пароль генерується випадковим
і показується **один раз** — збережіть його одразу.
