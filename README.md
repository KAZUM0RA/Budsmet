# Budsmet — веб-застосунок для складання будівельних кошторисів

Програма перетворює **обсяги робіт** на **заповнений кошторис із цінами**.

Два сценарії роботи:

1. **Об'єкт вручну.** Створюєте об'єкт (назва, адреса, місто), обираєте роботи з
   підказки і вписуєте обсяг — квадратуру, метраж або кількість. Програма підбирає
   ціну кожної позиції та рахує підсумки.
2. **Готова відомість обсягів робіт.** Завантажуєте порожній файл із переліком робіт
   і обсягами (PDF з АВК-5, XLSX або CSV) — на виході отримуєте заповнений кошторис
   у Excel, PDF або HTML.

Ціна кожної позиції визначається за трьома джерелами (порядок налаштовується):

| Джерело | Що це |
|---|---|
| **історія** | ціни з ваших попередніх кошторисів по цьому ж місту або області |
| **інтернет** | аналіз ринкових цін пошуком по місту об'єкта (потребує ключа доступу, див. нижче) |
| **довідник** | вбудована база розцінок із регіональним коефіцієнтом міста/області |

У таблиці кошторису біля кожної позиції видно, звідки взято ціну.

---

## Запуск

```bash
pip install -r requirements.txt
./run.sh                 # або: python3 -m uvicorn backend.main:app --reload
```

Відкрийте <http://127.0.0.1:8000>. База даних (`budsmet.db`) створюється автоматично
у корені проєкту; шлях змінюється змінною `BUDSMET_DB`.

Документація API — <http://127.0.0.1:8000/docs>.

## Аналіз цін в інтернеті

Типово вимкнено — застосунок працює офлайн на історії та довіднику. Щоб увімкнути,
задайте провайдера пошуку та його ключ:

```bash
export BUDSMET_PRICE_PROVIDER=serpapi   # serpapi | brave | google | custom | off
export SERPAPI_KEY=...                  # BRAVE_API_KEY / GOOGLE_CSE_KEY+GOOGLE_CSE_CX
./run.sh
```

Для провайдера `custom` вкажіть `BUDSMET_PRICE_ENDPOINT` — свій HTTP-ендпоінт, що на
запит `?q=…` повертає `{"results": [{"title": ..., "snippet": ..., "url": ...}]}`.

Програма формує запит виду «*назва роботи* ціна *місто* грн за *одиницю*», витягує
зі сніпетів суми у гривнях, відкидає ціни в інших одиницях виміру, розділяє їх на
роботи та матеріали і бере медіану. Результат кешується на 14 днів
(`BUDSMET_WEB_CACHE_DAYS`).

Інші налаштування: `BUDSMET_HISTORY_WINDOW` (скільки останніх цін усереднювати,
типово 8), `BUDSMET_WEB_TIMEOUT`.

## Як рахуються підсумки

```
Прямі витрати            = Σ (роботи + матеріали + машини) × обсяг
Загальновиробничі (ЗВВ)  = (роботи + машини) × %          ← матеріали в базу не входять
Разом                    = Прямі витрати + ЗВВ
Кошторисний прибуток     = (роботи + машини + ЗВВ) × %
Адмінвитрати, ризики     = Разом × %
ПДВ                      = (Разом + прибуток + адмін + ризики) × %
```

Відсотки редагуються для кожного об'єкта окремо; матеріали можна виключити з
кошторису одним прапорцем (коли їх постачає замовник).

## Довідник розцінок

`backend/data/price_catalog.json` — 182 позиції з цінами робіт, матеріалів та
експлуатації машин за одиницю (грн, без ПДВ). Покриває всі роботи з наданих
відомостей обсягів плюс типові загальнобудівельні, опоряджувальні, покрівельні,
сантехнічні та електромонтажні роботи.

**Ціни довідника — орієнтовні ринкові станом на серпень 2026 для Полтавської
області.** Їх варто звірити зі своїми фактичними розцінками: правити можна прямо в
інтерфейсі (вкладка «Довідник цін»), правки зберігаються в БД і перекривають файл.

`backend/data/regions.json` — коефіцієнти до базових цін: 25 областей і 32 міста
(Київ 1.35, Львів 1.22, Лохвиця 0.95 тощо). Коефіцієнт міста має пріоритет над
обласним.

## Як працює співставлення робіт

Найменування з відомості рідко збігається з довідником символ у символ, тому
співставлення робить `backend/services/matcher.py`:

1. нормалізація тексту — апострофи, латинські омоглифи (в АВК-5 «Розд**i**л» пишеться
   з латинською `i`), пунктуація, стоп-слова;
2. стемінг українських закінчень;
3. точний збіг за ключем «назва + одиниця виміру»;
4. інакше — нечіткий пошук `rapidfuzz` з бонусом за збіг одиниці виміру та штрафом
   за розбіжність.

Збіг нижче 62% вважається ненадійним — позиція лишається без ціни й підсвічується в
інтерфейсі, щоб її можна було оцінити вручну.

Пошук у полі «Найменування роботи» додатково враховує українську морфологію:
«розетк**а**» знаходить «розет**ок**», хоча як підрядок воно там не міститься.

## Структура проєкту

```
backend/
  main.py                 FastAPI: REST API + віддача інтерфейсу
  db.py                   SQLite: об'єкти, кошториси, позиції, історія цін, кеш
  config.py               налаштування та змінні середовища
  data/price_catalog.json довідник розцінок
  data/regions.json       регіональні коефіцієнти
  services/
    normalize.py          нормалізація тексту, одиниць виміру, чисел
    importer.py           розбір відомості обсягів робіт (PDF / XLSX / CSV)
    matcher.py            співставлення найменування з розцінкою
    catalog.py            довідник + правки користувача + регіони
    web_prices.py         аналіз цін в інтернеті (провайдери, кеш, медіана)
    pricing.py            вибір джерела ціни та розрахунок підсумків
    estimates.py          об'єкти, кошториси, перерахунок, історія
    exporter.py           вивантаження XLSX / PDF / HTML
frontend/                 інтерфейс (без збірки: HTML + CSS + ES2020)
samples/                  приклади відомостей обсягів робіт для перевірки
tests/                    44 тести (pytest)
```

## Тести

```bash
python3 -m pytest tests/ -q
```

Тести перевіряють, зокрема, що обидві реальні відомості з `samples/` розбираються
повністю — 116 і 129 позицій, наскрізна нумерація без пропусків, правильні одиниці
виміру та обсяги.

## API (основне)

| Метод | Шлях | Призначення |
|---|---|---|
| `POST` | `/api/import/preview` | розібрати файл і показати, що знайдено (без збереження) |
| `POST` | `/api/import` | створити об'єкт із файлу та проставити ціни |
| `POST` | `/api/import/fill` | порожній файл → одразу заповнений кошторис (xlsx/pdf/html) |
| `GET` | `/api/objects/{id}` | кошторис із цінами та підсумками |
| `POST` | `/api/objects/{id}/positions` | додати роботу з обсягом |
| `POST` | `/api/objects/{id}/reprice` | перерахувати ціни за обраною стратегією |
| `POST` | `/api/objects/{id}/history` | зафіксувати ціни кошторису в історії |
| `GET` | `/api/objects/{id}/export/{fmt}` | вивантажити `xlsx`, `pdf` або `html` |
| `GET` | `/api/price` | яка ціна і з якого джерела буде для однієї роботи |
| `GET`/`POST` | `/api/catalog` | пошук і редагування розцінок |

Приклад — заповнити відомість однією командою:

```bash
curl -F "file=@samples/vob_118_semenivka.pdf" -F "fmt=xlsx" \
     -o koshtorys.xlsx http://127.0.0.1:8000/api/import/fill
```
